# 2-5 Into Anything — instructions for Claude Code

Practice app for **passing chords** across genres: every way to get from one chord to the next
(the 2-5 is just one technique), plus modes, voicings, MIDI practice, and (being built) a
reharmonizer that reads the user's Logic MIDI files. The app started as a 2-5 tool; Phase 1
reframes it around all passing chords (see "Product direction" in docs/SPEC.md).

**Read `docs/SPEC.md` before any work.** It holds the full plan, the theory rules, the test cases
and the definition of done for every phase.

## The user
- Ralph, a pianist/producer working in Logic Pro on a Mac Studio, Native Instruments S88 keyboard,
  Kontakt pianos (NOIRE, Session Keys). Practices on Mac and iPad.
- Wants answers as very short bullets, not prose.
- Cares most that the music theory is right and that every suggestion says *why* it works.

## Hard rules
1. **Theory correctness beats features.** Every chord, spelling, voicing and analysis rule gets a
   unit test with a known-correct answer before it ships. If unsure about a rule, write the test
   case into `docs/OPEN_QUESTIONS.md` and ask instead of guessing.
2. **Correct enharmonic spelling.** Spell by letter steps (C Dorian has E♭ not D♯; A♭ major has D♭).
   Double sharps/flats are allowed when theory demands them; display with ♯ ♭ 𝄪 𝄫.
3. **Never break what works.** The features listed under "Existing features" in SPEC.md must keep
   working. Check them by hand (and with tests) after every phase.
4. **Static site only.** Hosted on GitHub Pages, no server, no accounts, no network calls at runtime
   except Google Fonts. Everything runs in the browser and works offline.
5. **Small commits**, one logical change each, message says what and why. Run tests before
   every commit.
6. **Explanations are generated by rules, not by an AI call.** Same input → same explanation.

## Stack (target after Phase 0)
- Vite + TypeScript (strict), no UI framework required (vanilla TS modules are fine; Preact allowed
  if the UI gets complex). Vitest for tests.
- `src/theory/` pure functions, no DOM. `src/midi/` file parsing + Web MIDI. `src/audio/` synth +
  MIDI out. `src/ui/` views. `src/data/` style presets and technique catalogue as typed data.
- Build to `dist/`, deploy with GitHub Actions → Pages (workflow in `.github/workflows/pages.yml`).
  Pages source must be set to "GitHub Actions" in repo settings (tell Ralph if it isn't).

## Service worker (important)
- Ralph has been bitten by stale service-worker caches before. Use **network-first for HTML**,
  cache-first for hashed assets, and put the build hash in the cache name. After deploy, the next
  app launch must show the new version.

## Commands
- `npm run dev`, `npm test`, `npm run build`, `npm run preview`

## When done with a phase
- Update the checklist in `docs/SPEC.md`, write a 5-bullet summary for Ralph (what's new, how to
  try it, what's not done), and list anything you could not verify.
